## 项目背景

**场景**：后台管理系统的侧边栏折叠——点击顶部导航栏的折叠按钮，左侧菜单栏从 264px 收缩到 64px，只显示图标。

**组件结构**：

```
BackendLayout.vue    ← 页面骨架（状态持有者）
├── SideBar.vue      ← 侧边栏（响应者）
└── NavBar.vue       ← 顶部导航栏（触发者）
```

---

## 核心实现

### 1. 状态提升到父组件

**为什么？** `collapsed` 被 NavBar 和 SideBar 两个兄弟组件都需要访问。如果放在任一个子组件里，另一个子组件就拿不到。所以**提升到共同的父组件 BackendLayout**。

```ts
// BackendLayout.vue
const collapsed = ref(false)
```

### 2. Props 向下传递（父 → 子）

```html
<!-- BackendLayout.vue 模板 -->
<SideBar :collapsed="collapsed" />
<NavBar :collapsed="collapsed" />
```

子组件声明接收：

```ts
// SideBar.vue
defineProps<{ collapsed: boolean }>()

// NavBar.vue
defineProps<{ collapsed: boolean }>()
```

### 3. Emit 向上通知（子 → 父）

NavBar 里的折叠按钮被点击时，不能直接改 prop（Vue 单向数据流），而是 emit 一个事件让父组件改：

```ts
// NavBar.vue
const emit = defineEmits<{ toggle: [] }>()
```

```html
<!-- NavBar.vue 模板 -->
<el-icon @click="emit('toggle')">
  <Fold v-if="!collapsed" />
  <Expand v-else />
</el-icon>
```

父组件接收事件并翻转状态：

```html
<!-- BackendLayout.vue -->
<NavBar @toggle="collapsed = !collapsed" />
```

### 4. SideBar 响应状态变化

不用写手动 DOM 操作，直接用 Element Plus 内置能力：

```html
<!-- SideBar.vue -->
<el-aside :width="collapsed ? '64px' : '264px'">
  <el-menu :collapse="collapsed" :collapse-transition="true">
  <!-- Element Plus 的 el-menu 内置了折叠动画、图标居中、tooltip -->
</el-aside>
```

---

## 完整数据流

```
NavBar 按钮点击
    ↓ emit('toggle')
BackendLayout collapsed 翻转（ref 响应式触发）
    ↓ :collapsed prop 重新绑定
SideBar el-menu :collapse 变化 → 自动折叠
SideBar el-aside :width 变化  → 宽度收缩
NavBar Fold/Expand 图标        → 条件渲染切换
```

## 面试官可能追问的问题

### Q1: 为什么不把 collapsed 放在 SideBar 里，然后 NavBar 直接操作它？

**答**：Vue 是**单向数据流**。父组件通过 props 向下传数据，子组件通过 emit 向上发事件。如果 NavBar 直接改 SideBar 里的状态，属于跨组件的直接状态修改，会导致：

- 数据流不可追踪（DevTools 里看不到谁改了状态）
- 组件耦合度高（NavBar 必须知道 SideBar 的内部实现）
- 违反 Vue 的设计哲学（props down, events up）

### Q2: 如果折叠状态还要被面包屑组件使用怎么办？

**答**：还是用状态提升。如果 BackendLayout 以上还有祖先组件需要，就继续往上提。如果多个不相关的组件都需要，就该引入 Pinia store（这时候可以引出状态管理的话题）。

### Q3: ref(false) 为什么改了会自动触发子组件更新？

**答**：Vue 3 的 `ref` 是响应式的。当 `collapsed` 在 BackendLayout 里被 `!collapsed` 重新赋值时：

1. Vue 的响应式系统检测到 ref 值变化
2. 重新执行 BackendLayout 的模板渲染
3. 新的 `:collapsed` prop 值传递给 SideBar 和 NavBar
4. 两个子组件的 defineProps 接收到新值，触发模板更新

这就是 Vue 的**声明式渲染**——我们只描述"状态是什么样，UI 应该是什么样"，不用手动操作 DOM。

### Q4: v-if="!collapsed" 和 v-show="!collapsed" 有什么区别？这里用哪个好？

**答**：

| 指令 | 行为 | 适用场景 |
|------|------|---------|
| `v-if` | 条件为 false 时**销毁** DOM 节点，条件变 true 时**重新创建** | 切换频繁、需要重新初始化的组件 |
| `v-show` | 条件为 false 时只切换 CSS `display: none`，DOM 始终存在 | 切换频繁、开销小的元素 |

这里用 `v-if`/`v-else` 切换图标（Fold/Expand），因为两个图标组件不会同时存在，用哪个都行。brand 区的文字隐藏用 `v-show`，避免频繁创建销毁 DOM。

## 可迁移的知识点

| 知识点 | 项目中如何应用 |
|--------|--------------|
| **单向数据流** | props 只读，emit 通知父组件修改 |
| **状态提升** | 多个组件共享状态时，提升到最近的共同祖先 |
| **Vue 响应式** | ref 值变化自动触发模板更新 |
| **Element Plus 内置能力** | `el-menu :collapse` 避免手动写折叠逻辑 |
| **条件渲染** | `v-if`/`v-else` 切换图标，`v-show` 控制显隐 |
